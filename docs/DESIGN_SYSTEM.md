# Interview Pal 设计系统

目标是安静、专业、有训练节奏的学习工作台。白色与冷灰蓝构成背景，深蓝文字建立可读性，teal用于主要动作和真实进展。避免把页面做成营销落地页或满屏高饱和数据仪表盘。

本文件是视觉与交互规范；下表已与当前`src/styles.css`核对。调整变量时同步更新本文件，不能让文档成为与界面脱节的第二套设计。

## 1. 色彩角色

| 角色     | 当前色值  | 用法                             |
| -------- | --------- | -------------------------------- |
| 应用背景 | `#F6F8F9` | 主工作区底色                     |
| 表面     | `#FFFFFF` | 卡片、表单、弹层                 |
| 次级表面 | `#F6F9F7` | 轻提示背景                       |
| 主文字   | `#1A343D` | `--ink`，标题与重要信息          |
| 正文     | `#243B43` | 根级正文颜色                     |
| 次级文字 | `#74828A` | `--muted`，元信息                |
| 细边框   | `#E8EDEF` | `--line`，卡片与分割线           |
| 主色     | `#087F72` | `--teal`，主按钮、选中状态和链接 |
| 主色悬停 | `#08665E` | `--teal-dark`，主按钮悬停        |
| 主色浅底 | `#EAF5F0` | 当前导航背景                     |
| 警示     | `#A17B43` | 警示标签，背景`#FAF3E7`          |
| 错误     | `#A76151` | 错误提示，背景`#FFF5EF`          |
| 成功     | `#378C78` | 成功标签，背景`#EDF7F1`          |

不要把“建议开始”画成“已经完成”。绿色只表达实际发生的成功，不表达随机填充的示例数据。

## 2. 字体与排版

- 中文优先系统无衬线字体，英文使用现代系统 sans-serif 回退；不依赖外部字体下载才能正常显示。
- 页面标题约28—34px，分区标题18—22px，正文14—16px，元信息12—13px。
- 英文题目可以略大，但避免全大写长句。
- 中文正文行高约1.65，英文回答约1.6；长内容控制阅读宽度。
- 主要标题、按钮和字段标签简短明确，说明文字写完整意思。
- 字号与边距在手机缩减，正文不因手机而压到难以阅读。

## 3. 空间与容器

基础间距采用4px倍数。常用间距8、12、16、24、32。桌面内容区两侧留白建议24—40px，手机16px。侧栏宽度宜在224—252px范围内，选中项使用浅底与深色文字，不使用厚重阴影。

当前普通卡片圆角为16px，输入和按钮为8px，桌面侧栏232px。阴影只用于浮层或少量主卡，常规卡片优先细边框。避免所有区块都像浮起的独立小窗。

## 4. 组件规则

### 按钮

- 主按钮：teal实底，每个区域只保留一个最主要动作。
- 次按钮：白底边框或浅灰底，用于编辑、查看要点、返回。
- 文本按钮：补充动作，仍具备清晰点击区域。
- 危险按钮：只在确有删除行为时使用；确认弹层写出删除范围。
- 请求进行时禁用重复提交并显示具体动作，如“正在生成反馈”。不要所有场景统一写“加载中”。

### 表单

字段标签常驻，不使用placeholder替代标签。可选字段明确标记。长文本区域保留合理高度，错误显示在字段附近。表单提交失败保留全部输入。

### 标签与状态

主题、难度、训练状态分别使用不同位置和语义，避免用同一种胶囊标签混在一起。状态必须有文字，如“待确认”“未配置”“本地保存”。不要只有颜色。

### 任务卡与题卡

顺序为任务/问题、必要说明、元信息、动作。整张卡可点击时，卡内次要动作必须避免事件误触。进度只能由实际记录计算，不能靠演示百分比填充。

### 录音控件

明确状态：准备、授权、录制、已停止、回放、转写中、失败。录制态显示计时和停止按钮。波形若只是装饰动画，应避免被理解为真实音量分析；没有分析时使用简单录制指示即可。

### 反馈卡

首先解释这是文本内容反馈还是语音反馈，再给总结、优先改进点和下一步。用户原话和AI建议用不同视觉层级表示。没有证据的维度显示未评估，不能用零分代替缺失。

### 命令面板

输入置顶，结果按页面/题目/动作分组。选中态对比清晰。弹层有背景遮罩，键盘焦点留在弹层内部，Escape关闭；手机面板避免被键盘完全遮挡。

## 5. 布局断点

| 场景        | 布局                                               |
| ----------- | -------------------------------------------------- |
| 宽桌面      | 左侧导航＋内容区；训练页可双列                     |
| 小桌面/平板 | 收紧间距；辅助面板落到主内容之后                   |
| 手机        | 顶部标题＋单列内容＋底部导航；页面主要动作保持可达 |

不要仅按屏幕宽度隐藏关键功能。手机仍需能够编辑稿件、录制、回放、阅读反馈和进入设置。水平表格应转换为卡片或允许受控滚动，不能撑开整页。

## 6. 文案风格

| 场景       | 推荐表达                                           | 避免                 |
| ---------- | -------------------------------------------------- | -------------------- |
| 无模型配置 | “配置模型后可生成内容反馈；现在可以先练习和记录。” | “AI已分析完成”       |
| 无语音评测 | “本次仅分析回答文本，尚未评估发音。”               | “口语80分”           |
| 简历缺结果 | “可补充真实结果，也可以说明尚未验证。”             | 自动补一个提升百分比 |
| 完成练习   | “你完成了这次回答，可以试试隐藏提示。”             | “你一定能通过面试”   |
| 请求失败   | “这次请求未完成，输入已保留，可以重试。”           | “发生错误”且清空内容 |
| 本地录音   | “录音仅供当前页面回放，刷新后可能不可用。”         | “已永久保存”         |

## 7. 动效与可访问性

动效用于解释状态变化，时长建议120—220ms。录音、错误和加载状态不依赖动效才能理解。支持 `prefers-reduced-motion`；键盘焦点轮廓不能被CSS移除。文字和背景对比度上线前需用工具检查，不以肉眼判断替代。

禁止使用虚假实时光标、随机闪动数字、无意义增长曲线制造“AI正在工作”的感觉。真实等待用稳定、具体的状态文案表达。
