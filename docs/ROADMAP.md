# Interview Pal 开发路线

状态日期：2026-10-10。本路线延续产品研究方案，但将“当前交付的本地开发版”与“未来可收费、可公开部署的产品”分开。工期、人数与学习阈值均为规划假设，不代表承诺或已验证结果。

## 1. 当前里程碑：本地开发版 v0.1

目标是让用户拿到代码后能够运行、体验完整页面流程、保存个人文本资料，并接入真实文本模型。它是可继续开发的基础，不是已经完成安全、支付、可靠性和教学验证的商业服务。

当前范围：

- 八个核心页面与响应式布局。
- 自我介绍、技术题、项目表达、复盘记录和个人资料的本地工作流。
- 浏览器localStorage保存非音频学习状态，支持明确的示例状态。
- MediaRecorder录音与当前页面Blob回放。
- Express代理真实LLM；独立配置兼容ASR服务。
- 明确的未配置状态、输入验证和错误反馈，不制造发音分。
- 代码、配置模板、页面设计、开发说明和验收清单。

以 `ACCEPTANCE.md` 和实际测试输出确认完成情况。若某项未经过真实模型、真实设备或真实用户测试，只能称为“已实现接口/流程，待验证”。

## 2. 阶段A：验证需求与反馈可信度

**先解决：用户真的缺什么，反馈是否值得信任。**

建议工作：

1. 访谈12—20位近期准备英文面试的算法工程师，了解具体卡住场景和已付费替代方案。
2. 从NLP、检索、RAG中选出最集中的首个岗位范围，不同时增加全部方向。
3. 以少量人工审核题簇和一个代表项目完成约两周辅助训练。
4. 比较未见问题的前后表现，包含放弃者和未改善者。
5. 用真实术语、口音和设备录音评估ASR及发音服务，不先相信供应商总分。

交付：访谈记录、限定岗位与难度、审核题簇样本、反馈错误集、前后测录音和盲评规约。

继续投入条件：问题足够集中；内容和反馈可用；用户愿意完成完整训练循环；出现真实付款或明确可验证的付费承诺。门槛必须在试验前约定，不能事后选一项好看的指标。

## 3. 阶段B：可邀请测试的受控服务

**先补齐：账号隔离、持久化和数据治理。**

| 工作           | 必须解决的问题               | 验收依据                             |
| -------------- | ---------------------------- | ------------------------------------ |
| 登录与鉴权     | 谁可以读写资料、调用付费模型 | 未登录不可访问他人数据或消耗模型额度 |
| 服务端持久化   | 多设备同步、版本冲突和恢复   | 刷新、换设备和服务重启不丢数据       |
| 文件与音频存储 | 授权访问、期限、删除范围     | 用户可导出/删除，链接失效可解释      |
| 事实和答案关联 | 更新简历后哪些稿件需要复核   | 仅提示受影响内容，历史版本可追溯     |
| 任务队列       | 生成超时、重试、重复调用     | 幂等任务不重复记账；输入不丢         |
| 监控与预算     | 错误、延迟和异常消耗         | 可定位失败，不在日志泄露简历和密钥   |

公开部署前必须通过鉴权与访问隔离检查。设置 `HOST=0.0.0.0` 或添加 CORS 域名不能代替这些能力。

## 4. 阶段C：首个可收费版本

保持一个领域，提供完整学习循环，而不是增加大量页面。

范围：

- 经技术与英语双重审核的题簇，明确内容来源和复审状态。
- 无稿、变式和项目追问；保留提示使用证据。
- 到期复习与简短录音式模拟。
- 可靠的内容评审，低置信度可反馈和人工复核。
- 订单、训练额度、费用说明、退款和失败返还。
- 个人数据导出/删除及运营后台。
- 真实付费用户的成本、效果与退款原因分析。

训练包可以优先研究14天或30天周期，但不意味着固定周期保证口语提升或录用。不要承诺无限实时对话。供应商赠送额度不能当作长期零成本，产品免费体验成本应计入获客模型。

进入下一阶段前，确认新问题上的改善，而非只有跟读分上涨或页面停留时间增加。

## 5. 阶段D：可靠的语音评测与实时模拟

语音评分和实时通话是两类能力，应分别验收。

### 专用语音评测

- 区分有稿朗读与无稿作答。
- 验证关键术语、合理口音、不同设备与音质。
- 评价可理解度，不把口音差异自动视作错误。
- 用户纠正转写不代表发音改善；有问题的自动对齐需复核。
- 若保留80分练习目标，必须限定引擎、任务和已校准样本范围。

### 实时面试

- 自然轮次、用户插话、暂停与恢复。
- 断连后按已完成题保存，不无限重复开场。
- 通话时显示时长与额度，不在用户说话中突然截断。
- 教练模式与面试模式分开，后者结束后统一复盘。
- 通话记录可回到专项训练，而不只是一个结束页面。

建议先做应用内语音，不接入真实电话网络。只有经过真实设备与网络测试后，才能声明响应时间或稳定性。

## 6. 阶段E：扩展第二个领域

依据真实需求、付费行为和审核人员供应，从搜广推、CV、语音、AI视频中选一个扩展。不要因为数据库已经定义了分类枚举，就宣称该方向的题库与评分已成熟。

每个新方向都应有：覆盖边界、题簇样本、审核负责人、错误案例、知识更新机制、少量真实用户验证。

代码判题、真人辅导市场、企业培训和社区属于独立产品方向，另做需求与成本验证，不挤入首个核心版本。

## 7. 研发优先级与依赖

| 优先级 | 事项                                   | 前置条件               |
| ------ | -------------------------------------- | ---------------------- |
| P0     | 事实不编造、输入不丢失、未配置不伪评分 | 所有生成和练习流程     |
| P0     | 本地页面闭环、模型接口与明确边界       | 本次交付               |
| P1     | 鉴权、持久化、数据隔离、服务成本控制   | 对外邀请或收费前       |
| P1     | 无稿迁移验证、内容审核与人工校准       | 宣称学习效果前         |
| P2     | 专用语音评测、实时模拟                 | 真实录音评测与预算通过 |
| P2     | 多计划与第二领域                       | 单领域价值获得证据     |

本地开发版中的“任务完成”和“文本内容较完整”不能直接成为商业版的“能力已掌握”。升级数据模型时需要迁移策略，保留原始证据与当时的评分版本。

## 8. 继续开发的操作纪律

1. 先运行项目和测试，再阅读 `PRODUCT_SPEC.md`、`DEVELOPMENT.md` 与实际源码。
2. 明确本轮只补哪个能力及对应验收，不为了“成熟感”补假图表或假历史。
3. 修改数据结构时提供版本迁移或导出恢复路径。
4. 修改模型、提示或题库时保留回归样例，检查事实编造与文本冒充语音评测。
5. 对当前未验证的外部API、价格和产品功能重新查阅官方资料。
6. 交付说明写清实现、验证和待办，不把本地构建成功说成上线完成。
