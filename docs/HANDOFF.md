# Interview Pal 交付与继续开发

交付日期：2026-10-10。仓库：`hellen9527/ai_interview_paln`。

## 本次落地

- 8 个应用页面：训练总览、学习路线、算法题库、项目故事、练习工作台、练习与复盘、面试档案、设置与数据。
- 首次示例清晰标注，无伪造历史。用户创建个人计划后移除示例人物和项目。
- 录入目标公司/岗位/JD；上传或粘贴简历；段落事实确认；项目五维编辑。
- 自我介绍生成/确认、浏览器示范朗读、逐句练习、关键词复述、无稿回答、录音上传与回听。
- 24 个有原始来源的算法题簇；全部标注待专家复审。
- 服务端调用文本模型和可选 ASR；没有 Key 时保留自主练习，不伪装生成成功。
- 内容反馈、真实原话引用校验、动态追问与实际问题快照；使用过辅助的尝试不会靠切换模式洗掉记录。
- 3/5 题模拟、保存后统一查看内容反馈、次日复习、历史导出、备份恢复与清除。
- 错误提示、空状态、响应式布局、键盘焦点、请求限制、音频/文件大小与文字长度约束。

## 运行与配置

以仓库根目录 README 为准。Node 22.12+，`npm ci`，复制 `.env.example` 为 `.env` 后：

- 开发：`npm run dev`，访问 `http://127.0.0.1:5173`。
- 构建与本地使用：`npm run build` 后 `npm start`，访问 `http://127.0.0.1:3001`。
- 检查：`npm test`、`npm run typecheck`、`npm run build`。

`.env` 留在本地。文本模型和 ASR 独立配置。API 只监听本机；直接挂公网之前必须完成鉴权和配额方案。

## 已执行验证与剩余验证

自动测试包括 API 协议/错误/安全边界、TXT/PDF/DOCX 实际解析、静态托管、存储恢复、复习去重、题库形状，以及 React 服务端渲染状态。当前 40 项通过，TypeScript 检查与生产构建通过。

LLM 和 ASR 使用模拟上游，**没有实际付费调用**。浏览器自动控制能力在本环境不可用，因此没有启动网页做浏览器视觉检查；SSR 只能验证渲染内容与状态，不能证明 CSS 视觉效果、点击流程或真实音频可用。请按 ACCEPTANCE.md 在桌面浏览器和手机进行验收。

依赖审计有 3 项中等风险传递依赖，无高危/严重项；当前文档解析只面向本地可信个人文件。对外服务需隔离解析，并在有兼容修复版本时升级，不强制降级掩盖风险。

## 下一轮优先顺序

1. **真实用户闭环**：请 5—8 位目标算法工程师，用真实但脱敏的履历完成一次介绍、技术题、项目题、反问和次日复练。观察无法独立开口的具体环节。
2. **模型对比**：在 DeepSeek Flash 与实际开通的 Doubao Mini 之间，用同一套样本比较事实保持、技术纠错、表达可学性、延迟和实际 token 成本。不要只比较单价。
3. **语音链路**：选定实际 ASR 与专业发音评测服务，先验证算法术语、弱口音和噪声场景。逐维显示证据，不从转写文本推断发音。
4. **生产数据层**：身份认证、PostgreSQL、对象存储、会话授权、逐用户限额、保留与删除策略；验证账号隔离再开放公网。
5. **实时模拟**：VAD、流式 ASR、低延迟 TTS、打断、弱网恢复、轮次控制和安全计费。当前逐题模拟不能替代这一工程阶段。
6. **题库与效果**：专家审核首批题簇，收集非标准正确答案，建立真实听懂率和迁移复测标准，再决定是否显示“80分”之类门槛。

## 当前实现的明确取舍

- 首期用确定的题库与个人项目要点驱动训练。没有实现简历技能图谱或自适应推荐算法。
- 项目事实由用户直接填写；模型不应补造职责、指标或已执行的实验。
- 长 JD 在反问内容评估中只使用开头 3,000 字；动态追问可使用完整已保存 JD。核心要求建议放在前面。
- 历史追问保留实际问题文本；“重练这个主题”回到原题簇，尚无任意历史追问精确重放。
- 每次保存按次日安排，按题目最近一次回答去重复习；没有实现成熟的间隔复习算法。
- 本地文字数据和录音生命周期不同：文字保存在浏览器，录音离开练习页后清除，下载文件由用户自行保存。
- 浏览器朗读音色与可用性取决于系统；不是服务端高质量 TTS。
- 备份文件属于个人资料，应自行妥善保管；客户端备份校验不等于多用户服务端权限校验。
