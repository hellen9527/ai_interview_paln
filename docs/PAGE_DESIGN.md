# Interview Pal 页面设计说明

本文件将产品方案转化为页面、交互、状态和字段规则。以下是设计要求，**不等于所有细节已在当前代码完成**。实现核对和未完成项应记录于 `ACCEPTANCE.md`；不得以设计稿替代运行结果。

## 1. 信息架构

主页面：今日训练、学习路线、题库、项目工作室、自我介绍练习台、复盘报告、资料与岗位、设置。

全局入口：品牌与首页、当前目标岗位、命令搜索、快速开始。桌面使用固定侧边栏和内容区；手机使用紧凑顶栏与底部导航，次要入口放入更多菜单或当前页操作，不能把八个图标挤满底栏。

| 层级 | 内容                     | 原则                       |
| ---- | ------------------------ | -------------------------- |
| 全局 | 当前岗位、搜索、快速开始 | 不与页面标题争夺视觉中心   |
| 一级 | 八个业务页面             | 命名一致，当前页状态可辨识 |
| 二级 | 当前任务、筛选、练习类型 | 只呈现与当前动作相关的内容 |
| 详情 | 题目、答案、录音和反馈   | 清楚指明正在练什么及下一步 |

## 2. 今日训练

**目标：让用户在数秒内理解今天的第一步。**

主要区域：

1. 简短欢迎与当前目标岗位，尚未填写时提供“完善目标”。
2. 主要任务卡：建议练习、原因、预计动作和一个明确开始按钮。
3. 学习路线摘要与进度，区分示例路线和真实完成记录。
4. 最近练习或待复练列表，无数据时显示空状态。
5. 快速入口：自我介绍、技术题、项目。

不能在首次打开时显示用户不存在的练习天数、已通过关卡、得分趋势或历史报告。建议任务可以由规则或种子内容生成，但需要称为“推荐”，不能冒充已分析出的个人弱点。

## 3. 学习路线

**目标：知道先练什么，以及什么状态才算完成。**

路线展示自我介绍、专业知识、项目表达、反问与沟通、模拟验证等学习目标。每项应有训练目的、任务入口和完成状态。

| 状态         | 表示什么             | 可用动作 |
| ------------ | -------------------- | -------- |
| 未开始       | 尚无实际尝试         | 开始     |
| 练习中       | 已产生草稿或尝试     | 继续     |
| 借助提示完成 | 依赖稿件或提示       | 试试无稿 |
| 独立完成     | 本次在无稿条件下完成 | 换个问法 |
| 待复练       | 用户标记或规则触发   | 复练     |

如果当前实现只有任务勾选，应将其称为“任务完成”，不升级为“能力已掌握”。用户应能够进入任何阶段，不以“80分”阻断后续学习。

## 4. 题库

**目标：找到与目标岗位相关的题，并进入真实作答。**

页面由主题筛选、难度筛选、关键词搜索、题卡列表和题目练习详情组成。推荐主题为基础评估、文本表示与检索、RAG/LLM 应用、工程实验。卡片显示英文问题、中文说明、主题、难度；不要以复杂标签填满卡片。

练习详情顺序：

1. 英文题目和中文问题意图；有示范语音时可播放。
2. 先自己回答：文本输入或录音。
3. 主动作“获取内容反馈”；次动作“查看要点”“生成追问”。
4. 返回结果后展示优先改进项和可继续的下一题。

无模型时仍能查看题目、填写或保存答案、自主复习；AI 动作说明需配置服务，不返回伪造结果。查看要点后，应避免把本次回答标记为完全无提示。

当前练习页提供可点击的原题参考出处和“待专家审核”说明。动态追问保存实际问题快照；评估追问时不沿用原题参考答案和评分点。同一尝试看过辅助后，切换“无稿”不会清除辅助历史。

## 5. 项目工作室

**目标：把项目事实整理为可以反复深问的英文叙述。**

信息区至少涵盖项目名称、背景目标、个人职责、技术选择、难点、结果。可以先录入不完整草稿，系统明确指出尚缺的信息，而不是替用户补造。

工作区包含中文事实、英文表达/回答区、追问区。生成动作前告知使用哪些资料；生成后可编辑。切换项目或清空表单前不得无提示覆盖未保存的内容。

项目结果为空时，提示“可以填写定性结果，或说明尚未验证”。缺少量化结果不阻止练习。个人职责和团队成果分开收集。涉及保密内容时支持用户主动匿名化。

动态追问应一题一题推进，不一次生成长篇审问清单。若当前代码仅支持单轮生成，应明确为“生成下一问”，不能叫完整的自适应面试官。

当前已提供中文要点到英文跟读的路径：先写真实中文要点，获取内容反馈及英文参考，保存本次反馈；核对事实后点击“用这段表达练习”，确认后载入本页逐句稿。用户可以取消使用；换题时清除，不自动写回项目事实。

## 6. 自我介绍练习台

**目标：从真实内容生成稿件，再逐步撤去辅助。**

桌面布局建议为资料/段落导航、当前练习区域、反馈摘要；手机按“稿件—录音—反馈”线性呈现。核心操作保持在可见范围，录音时不能被浮层或底栏遮挡。

流程：资料输入或引用 → 生成/编辑英文稿 → 确认符合经历 → 选句或整段 → 示范播放 → 录制 → 本地回放 → 可选转写 → 校对文本 → 内容反馈。

提示开关区分“完整稿”“关键词”“隐藏稿”。如果当前版本尚无自动关键词模式，可允许用户手填关键词，但不能把隐藏稿按钮等同于验证了独立应答。

录音上传必须由用户明确触发；本地回放不需要把音频发送给外部服务。语音合成不可用时仍允许阅读和录制。

当前上传录音上限为10MB，录制最长约5分钟。获取反馈或转写期间锁定会改变本次作答的关键输入；保存反馈前再次检查问题、回答和模式是否与请求快照一致。新追问清除上一问的临时录音，避免将旧音频误用于新题。

重录或替换文件前，存在未保存回答或临时音频时提示保存/下载；替换成功后清空旧文字和反馈，授权失败保留原内容。下载和转写保留上传文件的正确文件名；新录音按MIME命名。自主保存和AI反馈同样限制回答为15,000字符。

## 7. 复盘报告

**目标：反馈有依据，而且能回到练习。**

报告列表按实际练习时间排序，显示题目、输入形式和反馈状态。报告详情展示原回答、内容反馈、建议表达和下一步。若有数字评分，必须注明维度和依据，不能将内容分称为口语分。

无记录时展示“完成一次练习后，这里会保存你的复盘”，并提供入口。没有持久化音频时不显示永远可用的回放承诺；Blob 已失效应显示录音不可用，不使用无响应播放按钮。

用户应能分清：这次输入是手写文本、ASR 转写还是对真实音频做过专用评测。只有后者可以展示确有依据的语音结论。

## 8. 资料与岗位

**目标：一次建立必要资料，后续复用并可修正。**

优先支持简历/简介文本、目标职位、岗位方向、JD、面试时间、技术要点和项目。当前版本若未配置文件解析，应使用“粘贴简历”，不要放置一个假上传入口。

保存操作应有明确成功提示。离开页面不应让用户误以为表单已自动保存；若采用自动保存，需要说明保存时间与本地保存位置。

替换资料后提示重新检查依赖这份资料的稿件。完整事实级依赖更新和版本差异展示属于后续能力时，应如实标记，而不是对当前实现作保证。

### 字段规则

| 字段          | 规则                                   | 错误或空值处理               |
| ------------- | -------------------------------------- | ---------------------------- |
| 目标岗位      | 可为空；生成定制结果时说明使用通用岗位 | 不阻止浏览题库               |
| 简历/个人要点 | 生成个人介绍前至少有有效信息           | 就地提示补充内容             |
| JD            | 可为空；保持用户原文                   | 使用通用建议，不编造公司信息 |
| 面试日期      | 合法日期；过去日期只提醒               | 允许用户修正，不抹除资料     |
| 项目名称      | 项目保存时非空                         | 聚焦对应字段                 |
| 项目结果      | 可为空或“尚未验证”                     | 不自动生成数字               |
| 作答文本      | 去除首尾空白后非空才能反馈             | 不发送空请求                 |
| API Key       | 不进入业务表单、不写localStorage       | 使用服务端环境变量           |

输入长度限制须与 API 一致；前端说明字符上限，服务端再次验证。切勿在文档与代码使用互相矛盾的上限。

当前实现核对：资料保存要求填写目标岗位，未填时仍可浏览种子题库；若要实现上表的通用岗位保存路径，需要另行调整。简历解析已接入TXT/PDF/DOCX本地提取；候选事实按文本段落生成，需人工确认，不是已完成的智能履历核验。项目名称至少2个字、最多80字符；技术标签最多8个，每个最多30字符；项目五项正文每项最多1,600字符。

## 9. 设置

**目标：解释当前能力、数据和模型状态。**

展示 LLM、ASR 是否已配置，以及不含密钥的服务状态。配置指导引用 `.env.example` 和 `DEVELOPMENT.md`。不得在浏览器直接展示服务端密钥，也不要求把生产密钥填入持久化网页表单。

提供本地资料导出/清除或明确的管理指引。清除动作应二次确认范围；不能连同用户未选择的其他站点数据删除。未支持云备份时必须写明“仅此浏览器保存”。

## 10. 全局命令搜索与快速开始

命令搜索用于跳转页面、查找题目和发起常用动作。支持键盘快捷键时，应显示平台适配提示，打开后聚焦输入，Escape 关闭，关闭后恢复焦点。没有结果时提供清除筛选和页面入口。

快速开始默认打开推荐任务或简单选择器。不能偷偷修改用户资料、覆盖稿件或自动上传录音。搜索和快捷入口应复用同一页面/任务动作，不另造不同状态的数据副本。

当前实现的全局搜索主要搜索题目标题、英文问题与标签；完整页面与动作命令属于后续补齐项。快捷键已支持Ctrl/Cmd+K。页面入口仍通过导航到达，不将当前题目搜索称为已经覆盖所有动作的命令系统。

## 11. 页面状态矩阵

| 页面/能力  | 空状态               | 处理中                   | 成功                   | 失败/降级                            |
| ---------- | -------------------- | ------------------------ | ---------------------- | ------------------------------------ |
| 今日训练   | 首次训练引导         | 本地资料读取短暂占位     | 显示真实状态           | 数据损坏时保留恢复入口               |
| 学习路线   | 展示可开始路线       | 保存状态防重复点击       | 任务状态刷新           | 不把保存失败当作完成                 |
| 题库       | 搜索无结果           | AI反馈处理中             | 展示原回答与反馈       | 输入保留、可重试                     |
| 项目工作室 | 新项目引导           | 正在生成追问             | 问题对应当前项目       | 缺资料提示、模型错误可恢复           |
| 自我介绍   | 粘贴信息或自行写稿   | 生成、录音、上传分别标识 | 稿件与回放可用         | 禁止伪造生成稿/分数                  |
| 复盘报告   | 首次练习入口         | 报告保存/展开            | 真实尝试列表           | 音频失效单独说明                     |
| 资料与岗位 | 少量字段即可开始     | 保存或解析提示           | 告知本地已保存         | 不清空用户原输入                     |
| 设置       | 未配置模型是正常状态 | 检查服务状态             | 显示不含密钥的配置状态 | 显示连接失败与配置指引               |
| 录音       | 尚未授权             | 录制、停止、转写分开     | 本地回放/转写可校对    | 拒绝权限、无设备、格式不支持分别说明 |
| 命令搜索   | 常用动作             | 通常无远程请求           | 跳转正确页面           | 无结果可重置                         |

## 12. 移动端与无障碍验收

- 页面在常见手机宽度下无横向溢出，底部导航不盖住输入与录音操作。
- 触摸目标建议至少44×44 CSS像素，相邻危险与常用操作留出距离。
- 键盘能进入导航、按钮、输入和弹层；焦点可见。
- 录音状态使用文字和计时共同表达，不仅使用红色圆点。
- 图标按钮有可访问名称；错误提示关联对应字段。
- 尊重减少动画偏好，避免强闪烁与持续装饰动画。
- 不支持录音时仍有文本练习路径；文本路径不生成口语能力结论。
